# AES-128 Encryption/Decryption in Verilog

A hardware implementation of AES-128 encryption and decryption in Verilog, designed to process sensor data from CSV files. This is a module of the Scada Data Compression and Edge Analytics Project.

## Project Overview

This project implements AES-128 (Advanced Encryption Standard) encryption and decryption in hardware using Verilog. It reads sensor data (dynamic level and reservoir pressure) from a CSV file, encrypts it, decrypts it, and verifies the results.

## File Structure

### Core AES Modules

- **aes_core.v**: Core AES implementation containing S-box, inverse S-box, and key transformation functions. Handles the fundamental AES operations for both encryption and decryption.

- **aes_simple.v**: Simplified AES wrapper that coordinates the encryption/decryption process with round management and state transformations.

- **aes_encrypt.v**: Encryption module wrapper that instantiates aes_simple with encryption mode enabled.

- **aes_decrypt.v**: Decryption module wrapper that instantiates aes_simple with decryption mode enabled.

### Testbench and Data

- **aes_tb.v**: Main testbench that:
  - Reads sensor data from data.csv
  - Encrypts each row of data using AES-128
  - Decrypts the encrypted data
  - Verifies encryption/decryption correctness
  - Generates output CSV files and waveform data

- **data.csv**: Input CSV file containing sensor measurements (dynamic level in meters and reservoir pressure in atmospheres).

### Generated Files

- **aes_sim**: Compiled simulation executable (generated by Icarus Verilog)
- **aes_waveform.vcd**: Waveform dump file for viewing in GTKWave
- **encrypted_data.csv**: Output file containing encrypted sensor data
- **decrypted_data.csv**: Output file containing decrypted sensor data

## How It Works

1. The testbench reads CSV data containing sensor measurements
2. Each data row (64 bits total: 32-bit dynamic level + 32-bit pressure) is padded to 128 bits
3. The encryption module processes the plaintext with a predefined AES-128 key
4. The encrypted ciphertext is passed to the decryption module
5. The decryption module recovers the original plaintext
6. Results are verified and written to output CSV files
7. Waveforms are captured for analysis in GTKWave

## Prerequisites

- Icarus Verilog (iverilog) - for compilation
- VVP (Verilog simulation runtime) - included with Icarus Verilog
- GTKWave (optional) - for viewing waveforms

### Installing on Windows

Download and install Icarus Verilog from: http://bleyer.org/icarus/

### Installing on Linux

```sh
sudo apt-get update
sudo apt-get install iverilog gtkwave
```

### Installing on macOS

```sh
brew install icarus-verilog gtkwave
```

## Running the Simulation

1. Clone the repository:
```sh
git clone https://github.com/nottarun7/verilog-aes128-encryption.git
cd verilog-aes128-encryption
```

2. Compile the Verilog files:
```sh
iverilog -o aes_sim aes_simple.v aes_encrypt.v aes_decrypt.v aes_tb.v
```

3. Run the simulation:
```sh
vvp aes_sim
```

4. View the waveform (optional):
```sh
gtkwave aes_waveform.vcd
```

## Output

After running the simulation, you will find:

- **encrypted_data.csv**: Encrypted sensor data in hexadecimal format
- **decrypted_data.csv**: Decrypted sensor data in decimal format (should match original data)
- **aes_waveform.vcd**: Signal waveforms for debugging and analysis

The console will display:
- Progress for each row processed
- Encryption/decryption verification results (PASS/FAIL)
- Summary statistics
